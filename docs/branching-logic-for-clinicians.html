0About this guide & how the tool runs

This is a plain-English companion to the technical reference docs/branching-logic.md. It explains how the Autism A&P Builder decides what to put in your generated note, ABA letter, and IEP letter — without requiring you to read code or use Git. The goal is to give you enough understanding to predict, trust, spot, and explain the tool's behavior to a colleague.

How to open the tool

The Autism A&P Builder is a single HTML file (autism-ap-builder.html). Double-click it; it opens in any modern browser (Chrome, Edge, Firefox, Safari). No installation, no login, no internet connection required for the tool itself.

Where your inputs live

Everything you enter stays on your computer. The tool makes no network requests, sends no data to any server, and stores nothing on a remote service. PHI is safe to enter; nothing leaves your machine. The trade-off: there is also no "save" function. If you close the browser tab, your inputs are gone. The intended workflow is: fill out the form for one patient, copy the output to Epic (or wherever it belongs), then close. Treat each session as a one-shot.

What "copy to Epic" actually does

The copy buttons format the output specifically for paste-into-Epic — they convert the bracket placeholders (the yellow-highlighted {...} fields) into Epic's *** cursor-stop syntax. This lets you tab through the placeholders in Epic after pasting, filling in patient-specific details (dose, date, etc.) without leaving the keyboard. The preview area shows the placeholders highlighted; the clipboard receives the Epic-formatted version.

How to use this page

This is a reference doc — read it once cover-to-cover if you're learning the tool, then come back to specific sections when you want to look something up. The table of contents on the left jumps to each section. Within each section, the "Example: see this in action" boxes are collapsed by default; click to expand. The "for the technical detail" link at the bottom of each section takes you to the matching section of the technical reference for the codebase-level explanation.

A note about acronyms

This guide assumes familiarity with general clinical terms (DSM-5, ICD-10, comorbidity, ABA, IEP), but expands less common ones on first use. If you encounter an acronym that isn't expanded somewhere on the page, that's a documentation gap — flag it.

1How the tool turns your inputs into a finished note

There is no "save" button, and nothing is stored separately. Every time you check a box or change a dropdown, the tool re-builds your entire note from scratch using your current inputs. The A&P note, the ABA letter, and the IEP letter are not three different templates; they are three different views of the same underlying information.

This mental model — your inputs are the single source of truth, and the outputs are derived from them in real time — explains nearly everything else in this guide. When you change a comorbidity checkbox, the comorbidity appears in your A&P note, but it may also trigger a new referral in your plan, add language to the IEP letter, and shift the ABA letter's justification — because all of those outputs are reading from the same place.

The dashed boxes for the ABA and IEP letters reflect that they only appear as tabs when your patient is eligible for them. (Section 5 covers exactly when they appear and disappear.) The A&P note tab is always visible.

Three practical consequences

1. Changing an input changes everything that depends on it. If you copy the note to Epic, then go back and uncheck a comorbidity, your next copy will reflect the change — including in places you might not have expected, like the ABA letter's medical-necessity paragraph.

2. You can go back and change anything at any time. The tool re-renders from your current state on every change, so an input you set early in the visit can always be revised later — the output updates immediately to reflect it. The form does, however, have a natural top-to-bottom flow: some controls appear only after their parent input is set (for example, the trauma IEP opt-in only appears after you check the trauma comorbidity, and the cognitive-data-source question only appears after you select an ID or GDD profile). Filling the form in roughly its visual order helps make sure you see every relevant control; revising in any order is always safe.

3. What you see in the preview is exactly what you will copy. There is no hidden formatting, no "template" being filled in behind the scenes. If the preview reads correctly, the paste into Epic will too.

Example: see this in action

You are working on a note for a 4-year-old being evaluated for autism. You have entered the basics — preschool age group, suspected ASD, some social communication concerns — and you are looking at the preview.

Now you check the anxiety comorbidity box. Without you doing anything else, the preview re-builds:

  • The Assessment list grows a new line: "Anxiety disorder"
  • The Plan grows three new lines: a psychiatry referral, a psychotherapy referral, and PCIT (Parent-Child Interaction Therapy, because the patient's age qualifies for the parent-coaching evidence base)
  • The IEP Letter's accommodations section grows new bullets for a calm-down space and graduated exposure
  • An anxiety-specific override pill appears in the right-side panel, in case you want to suppress one of the new referrals

One checkbox; four downstream changes. None of it requires a save, a "regenerate," or another click. The note in your preview right now is the note you would paste.

2How the tool tailors output to the patient's age

Age is the most consulted input in the entire tool. More than fifteen separate decisions read your age-group selection — what services to recommend, which letter tabs to show, what language to use in the ABA letter, which screenings apply. Picking the right group matters; almost everything downstream pivots on it.

The five age groups

The tool offers five groups. The age ranges are clinical conventions, not hard cutoffs — pick the group whose developmental window best fits the patient.

  • Toddler (about 12–35 months) — IDEA Part C eligible (the federal early-intervention program for ages 0–2), no IEP yet, Early Steps is the Florida entry point
  • Preschool (about 3–5 years) — FDLRS (Florida Diagnostic & Learning Resources System) available if not yet in public school; NDBI-style (Naturalistic Developmental Behavioral Intervention) ABA framing
  • School-age (about 6–11 years) — school-based services under IDEA Part B (ages 3–21), FBA-style (Functional Behavior Assessment) ABA framing
  • Adolescent (about 12–17 years) — self-advocacy and consent education enter the picture
  • Young adult (18+) — workplace and legal-awareness framing

The big shifts to know about

The IEP Letter tab disappears for toddlers. Toddlers receive IDEA Part C services (in Florida, through Early Steps), not IEPs (which begin at age 3 under IDEA Part B). If you mark your patient as a toddler, the IEP Letter tab simply isn't there — by design, so you don't accidentally direct services to the wrong system.

The ABA letter language changes between young and school-age. For toddlers and preschoolers, the letter frames ABA in NDBI terms and cites the EIBI (Early Intensive Behavioral Intervention) evidence base. For school-age and older, it shifts to FBA-driven, functional-behavior language. Both are clinically appropriate to their age groups, but they read differently — useful to know if you're comparing letters across patients.

"Academics" is not a valid ABA target for school-age patients. If you check the academic-needs box for a school-age patient, the tool will not add "academics" to the ABA target list. This is intentional: school-age academic instruction is the school district's obligation under IDEA (Individuals with Disabilities Education Act), and listing it in an ABA letter creates a real risk of insurance denial. For toddlers and preschoolers, academics can appear (pre-academic skills are pre-Part B and fair game).

Several recommendations are age-gated. Social skills groups exclude toddlers (developmental fit) and young adults (psychotherapy is recommended instead). QbTest (a computerized attention measure used in ADHD evaluation) excludes patients under 6 (instrument norms). Early Steps fires only for toddlers; FDLRS only for preschoolers not yet in public school. The right group selection makes the right referrals show up automatically.

Cognitive profile options shift by age. The Cognitive Profile field on the Patient Profile shows different radio choices depending on age. For toddlers and preschoolers, intellectual disability (ID) tier options and the borderline intellectual functioning (BIF) option are hidden — under-5 patients can't have reliable IQ testing per DSM-5-TR and AACAP guidance, so the only relevant cognitive-impairment selections are the GDD tier. For school-age and older patients, the GDD tier hides and the ID/BIF options become available. If you switch a patient's age group between toddler/preschool and school-age+, any previously-selected cognitive profile that no longer fits will clear automatically, and the matching specifier (with-ID / with-BIF / etc.) will clear with it.

Cognitive data source instruments also shift between ID and GDD. When you pick an ID-tier cognitive profile, the Cognitive Data Source radio group lists IQ instruments — WISC, DAS, SB, WPPSI on the comprehensive line; KBIT-2R, RIAS-2, WASI-II on the brief-screener line. When you pick a GDD-tier profile, the same radio group switches to developmental instruments: Bayley-4, Mullen, Griffiths, DAYC-2 on the comprehensive line (DAYC-2 is what Florida Early Steps uses); ASQ-3 and the DAYC-2 Screener on the brief-screener line. The underlying behavior is unchanged — picking "comprehensive" still supports a confirmed diagnosis, picking "screener" or "clinical" still leaves the specifier as suspected — only the visible instrument list changes. If you switch a patient's cognitive profile across the ID↔GDD boundary, the Cognitive Data Source selection clears so you don't accidentally leave it on an instrument from the wrong tier. Additionally, if you pick "brief screener" for a toddler or preschooler, a small italic note appears under the field reminding you that brief screeners have documented floor effects in children under 5 — the result is best treated as preliminary pending formal developmental assessment.

What does not depend on age

A few things look like they should be age-gated but aren't — and shouldn't be. DSM-5 criteria (Section 4) apply identically across ages. The severity levels (Section 3) mean the same thing for a toddler and a young adult. The comorbidity list and its downstream effects (Section 6) don't change with age. If you find yourself wishing one of these did depend on age, double-check the clinical rationale — the age-independence is deliberate.

Example: see this in action

You're documenting a patient and you change the age group from preschool to school-age. With no other changes, here's what shifts:

  • The ABA letter's evidence section drops the EIBI/NDBI reference and shifts to FBA-driven language
  • If you had previously marked academic needs, the "academics" ABA target disappears from the target list
  • The FDLRS referral disappears from the Plan (FDLRS is preschool-only)
  • The QbTest recommendation becomes available (if ADHD is suspected)
  • If your patient was being referred to Early Steps, that referral disappears (toddler-only — preschool already excluded it)
  • The IEP Letter tab, which was visible, stays visible — school-age qualifies (assuming you've already selected a school-document status, which is the IEP tab's other gate; see Section 5)

None of these are bugs; each reflects a real clinical or regulatory difference between the two age windows.

3Why the tool asks for two severity ratings, not one

DSM-5 doesn't let you assign a single "Level 2" to ASD. It requires two separate severity ratings — one for social communication, one for restricted and repetitive behaviors — because a patient can need substantial support in one domain and only modest support in the other. The tool enforces this by giving you two independent dropdowns.

What the two dropdowns mean

Social Communication (SC) rates how much support the patient needs with social-communication deficits — initiating interactions, maintaining conversation, reading social cues, integrating verbal and nonverbal communication.

Restricted/Repetitive Behaviors (RRB) rates how much support the patient needs with restricted interests, repetitive behaviors, insistence on sameness, and sensory differences.

Each dropdown has the standard three options: Level 1 (requiring support), Level 2 (requiring substantial support), Level 3 (requiring very substantial support). You can also leave one or both blank.

How the tool combines the two

Several outputs need a single severity number — the ABA letter's medical-necessity paragraph, the IEP letter's diagnosis line, the badge in the header. When the tool needs one number, it uses the higher of the two domain ratings.

This is intentional and clinically conservative. A patient at Level 2 for restricted/repetitive behaviors and Level 1 for social communication gets the Level 2 narrative in their ABA letter — supporting the higher intensity of services their RRB severity justifies. If you'd prefer the letter to reflect the lower number, the override system (Section 7) won't help you here; you'd need to change the rating itself.

If you set only one of the two dropdowns, the tool uses whichever one you set. If you leave both blank, the letter falls back to language like "(level not specified)" — a signal to come back and complete the rating before sending.

Where each rating shows up separately

The A&P note prints both ratings independently, with their separate justification fields if you wrote them. The diagnosis line in both letters reads something like "Level 2 (Requiring Substantial Support) — Social Communication and Restricted/Repetitive Behaviors," naming both domains so the receiving clinician sees the full picture.

Example: see this in action

You're documenting a verbally fluent 8-year-old with significant sensory differences, intense restricted interests, and rigidity around transitions. Their social communication is mildly impaired but generally functional.

You set Social Communication = Level 1 and Restricted/Repetitive Behaviors = Level 2.

Here's what happens to the outputs:

  • The A&P note prints both ratings on separate lines, with whatever justification text you wrote for each
  • The ABA letter's medical-necessity paragraph uses the Level 2 narrative (the higher of the two), supporting more intensive ABA hours
  • The IEP letter's diagnosis label reads "Level 2 (requiring substantial support)"
  • The badge in the form header shows a combined "2" rating, with smaller ring indicators for each domain

If your patient's pattern were reversed (Level 2 SC, Level 1 RRB), the combined level would still be Level 2 — the rule picks the higher domain, not the average.

4How the tool checks whether you've met the DSM-5 bar

DSM-5 requires five things for an ASD diagnosis: all three of Criterion A (social-communication deficits), at least two of Criterion B (restricted/repetitive behaviors), and Criteria C, D, and E all met. The tool watches your selections in real time and tells you whether you've crossed the bar — but it won't stop you from documenting an exception you intend to make.

Reading the diagram top to bottom: you need all three Criterion A items, at least two of the four Criterion B items, and all three of C/D/E. Anything less puts you in the "incomplete" state.

What the criteria actually are

Criterion A is the social-communication trio: (a1) deficits in social-emotional reciprocity, (a2) deficits in nonverbal communicative behaviors, (a3) deficits in developing and maintaining relationships. You need all three.

Criterion B is the restricted/repetitive set: (b1) stereotyped or repetitive motor movements or speech, (b2) insistence on sameness or routines, (b3) highly restricted interests, (b4) hyper- or hypo-reactivity to sensory input. You need at least two of the four.

Criterion C: symptoms present in early developmental period.
Criterion D: symptoms cause clinically significant impairment.
Criterion E: not better explained by intellectual disability or global developmental delay alone.

What happens when criteria are incomplete

If you mark the diagnosis status as confirmed but the criteria don't all check out, the tool displays a warning banner at the top of the form: something like "⚠ DSM-5 criteria incomplete — A: 2/3 · B: 1/4 · C/D/E: missing C." The banner is intentionally prominent but it does not block you. The tool will still generate a confirmed-ASD A&P note and ABA letter if you proceed — on the assumption that you may have a clinically valid reason to document an exception (re-evaluation, follow-up after prior diagnosis, etc.). The warning's job is to make sure the omission is deliberate, not accidental.

If your diagnosis status is suspected or ruling out, no warning fires — partial criteria are expected at that stage.

One auto-cascade worth knowing about

Checking Criterion B2 (insistence on sameness) automatically marks "rigidity" as a behavioral need behind the scenes, which in turn adds "transitions" as an ABA target. This is the only criterion that auto-cascades into the needs and targets sections — chosen because B2 and rigidity are operationally the same thing. Unchecking B2 reverses both. If you ever wonder why "transitions" suddenly appeared in your ABA target list, this is usually why.

Example: see this in action

You are documenting a 5-year-old with clear social-communication deficits across the board, intense restricted interests, and notable sensory hyper-reactivity, but no observed motor stereotypies or insistence on sameness.

You check a1, a2, a3 (Criterion A complete), b3 and b4 (two of four Criterion B items — meets the minimum), and C, D, E. The badge in the header turns green: ✓ DSM-5 criteria complete.

Now you change your mind and uncheck b3. Criterion B drops to 1 out of 4 (just b4 remains), below the threshold. The badge turns yellow and a banner appears: "⚠ DSM-5 criteria incomplete — A: 3/3 · B: 1/4 · C/D/E: met." If you leave the diagnosis status set to confirmed, the warning persists but the letters still generate. If you change diagnosis status to suspected, the warning disappears.

5When the ABA and IEP Letter tabs appear (and when they hide)

The A&P Note tab is always there. The ABA Letter and IEP Letter tabs only appear when your patient is eligible — when generating the letter would actually make clinical and regulatory sense. If a tab disappears while you're looking at it, the tool automatically switches you back to the A&P Note so you don't end up staring at an empty pane.

Why each gate exists

The ABA Letter requires a confirmed diagnosis. The letter is a medical-necessity attestation for insurance authorization, and writing one without a confirmed ASD diagnosis would be clinically inappropriate. There is no way to generate this letter for a suspected diagnosis — you'd have to confirm first. The override system (Section 7) can force ABA to "included" for a patient who otherwise wouldn't trigger it, but it cannot bypass the confirmed-diagnosis check.

The ABA Letter also requires ABA to be a recommended service. If your patient's profile doesn't trigger any ABA-suggesting condition (severity, behavior, age, etc.), the tab stays hidden. If you believe ABA is warranted but the auto-rule disagrees, the override pill for ABA will force the tab to appear (assuming the diagnosis is also confirmed).

The IEP Letter requires a school-document selection. If you haven't indicated whether your patient is in public school, private school, or homeschool, the tool doesn't know how to frame the letter — so the tab stays hidden until you make that choice.

The IEP Letter is never available for toddlers. Toddlers receive Part C services through Early Steps; IEPs begin at age 3 under Part B. Writing an IEP letter for a toddler would route services to the wrong system. (See Section 2.)

What happens when a tab disappears mid-edit

If you're looking at the ABA Letter tab and then change something that hides it (e.g., you switch diagnosis status from confirmed to suspected), the tool automatically jumps you back to the A&P Note. The same happens with the IEP Letter tab. This prevents the confusing experience of "I was just here a second ago — where did the content go?"

Example: see this in action

You're working on a confirmed-ASD note for an 8-year-old in public school. Both the ABA Letter and IEP Letter tabs are visible. You're currently viewing the ABA Letter tab.

You realize you marked the diagnosis as confirmed too early — you actually want it set to suspected while you finalize one more screening. You change the dropdown.

Immediately:

  • The ABA Letter tab disappears (confirmed-diagnosis gate now fails)
  • You're automatically switched to the A&P Note tab
  • The IEP Letter tab stays visible (it doesn't depend on the diagnosis being confirmed)

If you later switch back to confirmed, the ABA Letter tab reappears — and you can click it again. The tool didn't delete or reset anything; the letter content rebuilds from your current inputs the moment the tab is available.

6What happens when you check a comorbidity

Checking a comorbidity box is rarely a one-line change. Most comorbidities trigger a coordinated cascade: the comorbidity appears in your A&P note with its ICD-10 code, the IEP letter grows new accommodation language, and one or more therapy or referral recommendations may fire. The cascade is intentional — a single click produces a full documentation update.

The cascade in plain language

For each comorbidity you check, the tool does up to three things:

  1. Adds it to the A&P note with the correct ICD-10 code and clinical phrasing. (You can also separately decide whether each comorbidity appears in the Plan section via a "show in Plan" checkbox.)
  2. Adds matching language to the IEP letter — education-focused phrasing about classroom accommodations, executive function supports, mealtime protocols, etc.
  3. Fires any therapy or referral recommendations that the comorbidity warrants — e.g., anxiety triggers psychiatry, psychotherapy, and PCIT (for younger patients). See Section 7 for how the recommendation rules work.

The trauma opt-in

Trauma is the one comorbidity that does not automatically appear in the IEP letter. The reason: the IEP letter goes into the educational record, which has different privacy and access properties than the medical record. By default, the tool documents trauma in your A&P note (medical chart) but omits it from the IEP letter. If you decide the school needs to know — to coordinate trauma-informed accommodations, for example — you can check a small opt-in box that appears once trauma is selected. When you opt in, a warning banner appears at the top of the IEP letter preview to make the inclusion deliberate.

One mutual-exclusion rule

Specific learning disabilities have a small twist: if you check any of the confirmed-domain options (reading, math, or written expression), the "suspected SLD" box clears automatically — and vice versa. The two states are clinically incompatible (a patient can't be both certainly diagnosed and uncertainly suspected with the same condition), so the tool enforces the exclusion for you.

Example: see this in action

You're documenting a 7-year-old with confirmed ASD, attention concerns, and reading struggles. You check three comorbidity boxes: ADHD (combined), SLD — reading, and anxiety.

With three clicks, here's what the documentation now contains:

  • The Assessment list grows three lines with the F90.2, F81.0, and F41.x codes
  • The Plan adds: psychiatry referral (for ADHD and anxiety), psychotherapy referral (for anxiety), QbTest (school-age, ADHD), and PCIT is suggested because of the patient's age
  • The IEP letter accommodations section grows: extended time and preferential seating (ADHD), text-to-speech and audiobooks (reading SLD), calm-down space and graduated exposure (anxiety)
  • The override panel grows new pills for each of the new referrals, in case you want to suppress one

Total clicks: three. Total documentation produced: about 12 distinct additions across three outputs.

7How therapy and referral recommendations are decided — and how to override them

Every therapy and referral the tool can recommend goes through a two-step process. First, an automatic rule decides whether the recommendation would fire by default based on the patient's profile. Second, a per-recommendation override pill in the right-side panel lets you force it on, force it off, or accept the default. Eighteen separate rules cover everything from ABA to genetics to QbTest, and they all follow this same shape.

The two-step shape

flowchart LR A["Patient profile
(your inputs)"] --> B["Auto-rule
(e.g. 'Should ABA fire
for this patient?')"] O["Override pill
(auto / force-on / force-off)"] --> R B --> R{"What does the
override say?"} R -->|Auto| RA["Use what the
auto-rule decided"] R -->|Force on| RY["Recommend it
(regardless of rule)"] R -->|Force off| RN["Don't recommend it
(regardless of rule)"]

Every recommendation in the tool follows this exact pattern. If you understand it for one recommendation, you understand it for all eighteen.

What the auto-rules look at

Each rule asks one clinical question and answers "yes" or "no." A few representative examples:

  • ABA fires if the patient is a toddler or preschooler, OR is minimally verbal, OR has confirmed intellectual disability, OR has significant adaptive impairment, OR has behavioral/safety needs, OR is at ASD Level 2 or 3 in either domain. (Any one of these is enough.)
  • Genetics fires for any confirmed ASD diagnosis, OR — if diagnosis status is suspected — for any patient with intellectual disability, developmental regression, dysmorphic features, congenital anomalies, or focal neurological findings.
  • QbTest fires when ADHD is suspected AND the patient is school-age or older. (The age gate is because QbTest's normative data starts at age 6.)
  • Early Steps fires only when the patient is a toddler AND a diagnosis is either confirmed or suspected.

The other fourteen rules follow the same pattern — each one a focused clinical question with a yes/no answer. The technical reference has the full list with line-by-line conditions.

The override pills

Each rule has a pill in the right-side panel labeled with the recommendation name. The pill cycles through three states each time you click it: auto → force on → force off → auto.

  • Auto (the default) — the recommendation follows whatever the auto-rule decided. The pill background is soft blue when the rule says yes, or soft gray when the rule says no. You can tell at a glance which recommendations the tool is suggesting.
  • Force on — the recommendation is included regardless of the rule. The pill turns a saturated green. Use this when you want to recommend something the auto-rule didn't catch.
  • Force off — the recommendation is excluded regardless of the rule. The pill turns dim gray. Use this when the auto-rule fires something you've considered and decided against (e.g., the family declined a referral).

The visual distinction between "auto says yes" (soft blue) and "force on" (saturated green) is intentional: at a glance, you can tell which recommendations came from the tool's logic and which you actively pushed in. This matters when you're reviewing a colleague's note or your own note from a previous visit — the override states are a record of your clinical judgment, not just passive defaults.

One important thing the override does not do

The override system controls whether a recommendation is included. It does not bypass the hard gates on the letter tabs (Section 5). You can force ABA "on" for a patient with a suspected (not confirmed) diagnosis — the ABA section will appear in the form, and the recommendation will fire — but the ABA Letter tab will still be hidden until you change the diagnosis status to confirmed. The override is for clinical content; the letter gate is for documentation appropriateness.

Example: see this in action

You are documenting a 4-year-old with confirmed ASD, behavior concerns, and Level 2 social-communication severity. No overrides set yet — everything is on auto.

The ABA pill turns soft blue (auto says yes — multiple triggers fire) and the ABA Letter tab is visible.

The patient's parents have asked you to also pursue a genetics consult, even though no specific genetic features are present. The Genetics pill is currently soft blue (the auto-rule fired because the diagnosis is confirmed). Genetics is already going to be recommended — nothing to do.

But on PT: the auto-rule sees no gross-motor needs and no DCD comorbidity, so the PT pill is soft gray (auto says no). The parents have flagged that the child trips often and tires quickly on stairs — you want PT recommended anyway. You click the PT pill once: it turns saturated green (force on). The Plan section now shows a PT referral, and any letter content that mentions services now includes PT.

Later, you decide that the psychiatry recommendation that auto-fired (because of severe behaviors) is too aggressive for this family right now — they want to try behavioral interventions first. You click the Psychiatry pill twice: auto → force on → force off. It turns dim gray. The psychiatry line disappears from the Plan, and your decision-to-defer is recorded in the override state.

8How the tool handles pronouns and gendered language

The tool generates a lot of prose — full paragraphs about the patient that read naturally as English sentences. To do that, it needs to know which pronouns to use. You pick from he, she, they, or leave it blank for a noun-phrase fallback ("the child" or "the individual" depending on age). The tool then handles the grammar for you.

The four pronoun options

  • he — "He demonstrates...", "his profile...", "himself..."
  • she — "She demonstrates...", "her profile...", "herself..."
  • they — singular "they"; "They demonstrate...", "their profile...", "themselves..." (note the plural verb form)
  • blank — falls back to a noun phrase: "the child" for younger patients, "the individual" for adolescents and young adults

Why singular "they" is a small grammatical landmine

If you pick they, every sentence about the patient needs the plural verb form. "They demonstrate" is correct; "They demonstrates" reads as broken English. The tool handles this by translating verbs through a small lookup table when the pronoun is set to they — "demonstrates" becomes "demonstrate," "is" becomes "are," "has" becomes "have," and so on.

The table covers the verbs the tool actually uses in its generated prose. If a future verb gets added to the prose without being added to this lookup table, the singular-they sentence will read ungrammatically without any warning to you. There's a maintenance audit (in the technical reference) that the tool's author runs when prose content is added, but it's not automatic.

The noun-phrase fallback

When you leave the pronoun field blank, the tool falls back to a generic noun phrase keyed to age:

  • Toddler, preschool, school-age → "the child"
  • Adolescent, young adult → "the individual"

This is meant as a graceful default for cases where the pronoun hasn't been entered yet or the family hasn't specified. Note that this generic phrasing also affects how possessives read ("the child's profile") and the reflexive form (recently fixed to use "themselves" — the singular-they reflexive — to avoid the awkward "the childself" output the prior version produced).

What this means in practice

Pick the pronoun early. Pronoun selection threads through every paragraph the tool generates. Changing it mid-edit is fine — the tool re-renders the note instantly — but it's one of those inputs that's easy to forget.

If the family has specified a pronoun, use it. The tool supports he, she, and singular they. If the family has indicated a preference, the prose should reflect it; the noun-phrase fallback is a last resort, not a default.

If you spot ungrammatical output, flag it. A "they presents" or "they has" anywhere in your generated note is a sign that a verb was missed during a content addition. Report it so the lookup table can be updated.

Example: see this in action

You are documenting a verbally fluent 10-year-old whose family has indicated they use they/them pronouns. You set the pronoun dropdown to they.

The A&P note's prose now reads naturally with the plural verb forms:

Excerpt from A&P noteThey are a 10-year-old presenting for a follow-up evaluation of autism spectrum disorder. They demonstrate good basic conversational skills with familiar adults but have difficulty initiating play with peers. Their sensory profile is notable for hyper-reactivity to loud environments...

Compare to the same note with pronoun set to blank:

Excerpt with blank pronoun (school-age fallback)The child is a 10-year-old presenting for a follow-up evaluation of autism spectrum disorder. The child demonstrates good basic conversational skills with familiar adults but has difficulty initiating play with peers. The child's sensory profile is notable for hyper-reactivity to loud environments...

Both are grammatical and clinically usable; the pronoun version is more natural for clinical reading and respects the family's stated preference.

9What goes into the ABA Letter, and what's deliberately left out

The ABA Letter is a medical-necessity attestation for insurance authorization. Its content is assembled from your inputs in a specific order — diagnosis, severity, functional impairment, target behaviors, settings, and dosing — and a few things are intentionally omitted because including them would weaken the authorization. Understanding what's in (and what's not) helps you read the generated letter critically before sending.

The hard gate

The ABA Letter only generates when the diagnosis status is set to confirmed. There is no path to the letter from a suspected or rule-out status. (See Section 5.) This is by design: writing a medical-necessity letter without a confirmed diagnosis is clinically inappropriate.

What the letter contains

A diagnosis line stating ASD with the combined severity level (the higher of your two domain ratings — see Section 3) and naming both domains. Example: "Level 2 (Requiring Substantial Support) — Social Communication and Restricted/Repetitive Behaviors."

A medical-necessity paragraph that explains why ABA is warranted for this specific patient. The paragraph lists the reasons the auto-rule fired — age, severity, behavior needs, safety concerns, etc. — and is the section most likely to determine whether the insurer authorizes.

A functional impairment paragraph that describes the domains where the patient demonstrates clinically significant impairment, based on which needs categories you've checked (communication, behavior, social, sensory, motor, adaptive). If any safety flags are present (SIB, elopement, aggression, pica), the paragraph adds an urgency clause.

A target list of behaviors ABA will address. Targets auto-populate from your needs and clinical-flag selections (see "How targets get populated" below). You can also manually add or remove targets via the checkboxes in the ABA section of the form.

A settings section listing where ABA should be delivered (home, clinic, school, community, telehealth — whichever you checked) and the recommended hours per week.

Specifiers that contextualize the diagnosis when relevant (intellectual disability, language impairment, genetic condition, etc.). Note the omissions below.

How targets get populated

The tool's "auto-populate ABA targets" feature watches your needs and clinical flag selections and adds matching targets automatically. For example, checking "elopement" under behavior needs auto-adds "reduce_elopement" to the target list; checking "expressive communication" auto-adds "functional_comm"; checking "menstrual care" under adaptive needs auto-adds "menstrual_care."

This auto-population is one-directional — it only adds. If you uncheck a target manually, the tool will not re-add it the next time you open the form. This is intentional: it protects your manual curation from being overwritten by surprise re-population. The only exception is rigidity, which is tied to Criterion B2 (see Section 4) and resets if you uncheck B2.

Practical consequence: if you've manually removed a target you don't think applies, it stays removed. If you want it back, re-check it manually.

What's deliberately left out

The "without intellectual disability" and "without language impairment" specifiers do not appear in the ABA letter, even when you've checked them. The reasoning is authorization-focused: these "absence" specifiers don't help establish medical necessity for ABA and, in the insurance reviewer's eyes, can be read as weakening the case for intensive services. The A&P note still prints them (because they're clinically accurate documentation); the ABA letter omits them because the letter has a different audience and purpose.

If you spot a specifier missing from the ABA letter that's in your A&P note, this is usually why. It's not a bug; it's an intentional omission.

Example: see this in action

You are writing an ABA Letter for a 5-year-old with confirmed ASD, Level 2 social communication, Level 1 RRB, and significant behavior concerns. You've checked: tantrums, aggression, expressive communication needs, and sensory needs. ABA hours: 25 per week, in clinic and home.

The generated letter contains:

Diagnosis lineAutism Spectrum Disorder (ICD-10: F84.0) — Level 2 (Requiring Substantial Support) — Social Communication and Restricted/Repetitive Behaviors
Medical-necessity paragraph (excerpt)Applied Behavior Analysis is medically necessary given preschool age group, behavioral support needs, and ASD Level 2 or 3 severity. The patient demonstrates clinically significant functional impairments across expressive and/or receptive communication; behavioral regulation; and sensory processing and integration...
Target list (auto-populated from your needs selections)• reduce_tantrum • reduce_aggression • functional_comm • imitation • joint_attention

What you do not see in the letter: any "without" specifier you may have checked, even though those will appear in your A&P note. If you manually uncheck "imitation" because you've decided it's not a current priority for this family, it stays unchecked — the auto-populator will not re-add it on your next visit.

10What goes into the IEP Letter, and the trauma opt-in

The IEP Letter is written to the school team to support an Individualized Education Program (or 504 plan, depending on placement). Unlike the ABA letter, it does not require a confirmed diagnosis — it can fire for suspected ASD too, using "under evaluation" framing. Its content is organized around educational impact: how the patient's profile affects learning, what services the school should provide, and what accommodations belong in the IEP.

The diagnosis label

The letter's opening diagnosis line shifts based on diagnosis status:

  • Confirmed → "Autism Spectrum Disorder (ICD-10: F84.0)" plus the severity level
  • Suspected → "Autism Spectrum Disorder — under evaluation (ICD-10: Z03.89)"
  • Rule-out → "Neurodevelopmental evaluation (ICD-10: Z03.89)"

The Z03.89 code (encounter for observation for suspected disease, ruled out) is the right placeholder for not-yet-confirmed cases; the school team can interpret the framing appropriately.

What the letter contains

An educational impact section that translates each of your patient's checked needs categories into classroom-facing language: communication difficulties affect classroom participation, behavioral concerns affect safety and self-regulation, sensory differences affect attention and arousal, etc. Each domain becomes a bullet only if you've checked something in the corresponding needs category.

A services-recommended section with rationales for any school-based services you've selected: speech therapy, OT, PT, counseling, social skills, paraprofessional support, extended school year, low student-to-teacher ratio, and so on. Each service block names the goals and the rationale, so the school's team can match the request to their service catalog.

An accommodations section with four sub-categories:

  1. Core accommodations — universal ASD-friendly supports that every student receives unless explicitly excluded (predictable schedule, visual supports calibrated to developmental level)
  2. Individual accommodations — sensory, motor, and language-specific supports triggered by the needs categories you've checked
  3. ID-modification accommodations — modified curriculum and alternate assessment, included only when intellectual disability is confirmed (not suspected) and the "with ID" specifier is set
  4. Behavioral, emotional, and feeding accommodations — comorbidity-driven supports (anxiety calm-down spaces, ADHD extended time, ARFID safe-food protocols, epilepsy seizure plans, etc.)

An academic accommodations section for any learning disabilities you've documented — text-to-speech for reading SLD, calculator access for math SLD, speech-to-text for written-expression SLD, and so on.

The trauma opt-in

If you've checked trauma as a comorbidity, the IEP letter will not include any reference to it by default. A small opt-in checkbox appears once trauma is selected: "Include trauma in IEP letter." The default is unchecked.

The reason: the IEP letter goes into the educational record, which has different privacy and access properties than the medical record. Including trauma in an educational document means it may be visible to school staff, substitute teachers, and (in some districts) administrative reviewers who don't need to know. Excluding it by default protects the family's privacy unless you specifically decide the school needs to know to coordinate trauma-informed accommodations.

If you do opt in, a yellow warning banner appears at the top of the IEP letter preview to make sure the inclusion is deliberate and reviewable before you send.

One ID-specifier edge case

If you've checked "with suspected ID" or "with suspected GDD" but the cognitive data didn't come from a formal prior external evaluation, the IEP letter adds a note: educational eligibility under the ID category should not be assigned on the basis of this letter alone, and a comprehensive psychoeducational evaluation is required per IDEA. This protects the school from over-assigning a categorical eligibility based on suspected (not confirmed) findings, and protects the patient from being prematurely tracked into modified curriculum.

Example: see this in action

You are writing an IEP Letter for a 9-year-old with confirmed ASD, Level 1 severity in both domains, mild anxiety, and a confirmed reading-domain learning disability. The patient is in public school. You've selected the following school services: SLP, counseling, sensory accommodations, visual supports, and psychoeducational evaluation.

The letter contains:

  • A diagnosis line: "Autism Spectrum Disorder (ICD-10: F84.0) — Level 1 (requiring support)"
  • A list of comorbidities: anxiety disorder, specific learning disorder in reading (dyslexia)
  • An educational impact section noting communication, social, and SLD-reading impacts on classroom function
  • Service-rationale blocks for SLP (with goals for pragmatics and conversation skills), counseling (anxiety-focused), sensory accommodations (in coordination with OT consult), visual supports (daily schedule, transition warnings), and a psychoeducational evaluation (to characterize reading-SLD scope)
  • Accommodations: predictable schedule and visual supports (core); anxiety calm-down space (behavioral); text-to-speech, audiobooks, and extended time (academic, for reading SLD)

No mention of any trauma history, even if it's in the A&P note, unless you opted in.

11Places where the tool can quietly go wrong — and what to watch for

The tool's biggest risk isn't a crash or a freeze — it's silently producing slightly wrong output that you don't notice until it's already in the chart. This section catalogs the known fragile areas: places where a mistake can slip through without any warning. Knowing where to look helps you catch problems before they reach the patient's record.

Ungrammatical singular-they verbs

As described in Section 8, when you pick they as the pronoun, every verb about the patient needs the plural form. The tool translates verbs using a lookup table, but the table covers only the verbs that were known at the time the prose was last updated. If a new sentence is added to the generated note using a verb the table doesn't know, you'll get output like "They presents with..." or "They has a history of..." — ungrammatical, but without any in-app warning.

What to watch for: any verb ending in -s immediately after "they" in your generated note, ABA letter, or IEP letter when the pronoun is set to they. If you see one, flag it.

Auto-populated ABA targets that no longer apply

The ABA target auto-populator adds targets when you check needs, but it only adds — it never removes. If you check a need, then later uncheck it (or the underlying clinical picture changes), the ABA target stays in the list until you manually uncheck it. This is intentional protection against surprise loss of manually-curated targets, but it means a stale target can linger.

What to watch for: before sending an ABA letter, scan the target list. Anything that no longer reflects current clinical priorities should be manually unchecked.

Severity ratings left blank

If you forget to set both severity ratings (Section 3), the ABA letter falls back to the language "(level not specified)" in its medical-necessity paragraph. The letter still generates, but it reads as incomplete to the insurance reviewer.

What to watch for: the header badge ring shows the combined level visually. If it's empty or grayed, you haven't set the severities yet.

Stale overrides during a long evaluation session

During a long visit, you may set an override pill to force-on or force-off early in the session — based on the patient information you had at that moment — and then forget to revisit it after the clinical picture changes. The tool does not auto-revert an override when its underlying rationale no longer applies. The "force on" green and "force off" gray pills are visually distinct from "auto," but they're easy to miss when you're focused on filling in new information later in the visit.

What to watch for: at the end of a visit, do a quick scan of the override panel. Any green or dim-gray pill should be a deliberate, still-current choice, not a leftover from earlier in the session.

Note: the tool does not save state across browser sessions (see Section 0). Closing the browser resets every override back to auto on next open.

Specifier mismatch between cognitive profile and ID specifier

When you change the cognitive profile dropdown (e.g., from "average" to "ID, moderate"), the tool automatically updates the matching ID/GDD/BIF (Borderline Intellectual Functioning) specifier to keep them in sync. But the auto-update fires only on specific control changes; if you set the specifier manually first and then change the cognitive profile, the manual change will be overwritten. This is by design (the cognitive profile is treated as the source of truth), but the silent overwrite can surprise a clinician who set the specifier deliberately.

What to watch for: if you've made a deliberate manual choice on an ID specifier, set the cognitive profile dropdown first, then make the specifier adjustment. Reverse order risks losing the manual choice.

Trauma defaults to omitted from the IEP letter

This isn't a bug — it's the intentional behavior described in Section 10 — but it's worth keeping on the watch-list. If you check trauma as a comorbidity and assume it will appear in both letters automatically, the IEP letter will omit it. If you want it included, you have to opt in explicitly.

What to watch for: after checking trauma, decide consciously whether the school needs to know. The opt-in checkbox is the only path; defaulting to omission is the safe direction for patient privacy.

The pattern

The fragile areas share a common shape: the tool does something silently and reasonably, but if the underlying assumption no longer holds, you won't get a warning. The remedy is the same in every case: before you send a note or letter, do a quick scan of the output for the specific things above. None of them are common — but each has been chosen for this section because it has happened, or could plausibly happen, without obvious in-app feedback.

12How this document is maintained

This guide is a living document: it is intended to stay accurate as the underlying tool evolves. It is stored alongside the program's source code, updated whenever changes to the program would otherwise leave the guide stale. This short section explains the chain it sits in, when to update it, and how to verify the update.

Where this document fits

The Autism A&P Builder has two reference documents, and they form a chain. The first link in that chain is the program itself — the source code. The second link is the technical reference, written for the maintainer and for future Claude Code sessions making changes to the program. The third link is this guide, which translates the technical reference into the plain English a non-programmer clinician needs.

Read the chain as: code is the source of truth; the technical reference describes the code; this guide describes the technical reference. When a change ripples through, it flows in the same direction — and each step in the chain is responsible for staying in sync with the step above it.

When this guide should be updated

  • Whenever a change to the program affects user-visible behavior — a new rule, a changed gate, a renamed UI element, an output that now reads differently. If a clinician would notice the difference, this guide should reflect it.
  • Whenever the technical reference is updated. If the technical reference has a new section, a renumbered section, or a substantive change to an existing section, this guide should be checked for the corresponding update.
  • Whenever a vignette in this guide no longer matches what actually happens. Vignettes are the most concrete claims in this guide, so they're also the most likely to drift if the program changes underneath them. A wrong vignette is worse than no vignette.
  • Whenever a clinical term or acronym used in the program changes. If the form's labels shift, this guide's prose should too.

The verification checklist

The first five steps below can be done by anyone using the guide. The last two are technical and live with whoever is maintaining the project (a developer or a Claude Code session). If you are a clinician noticing a problem, the first five let you confirm the problem is real — then hand off to the maintainer for the technical save.

  1. Open this file in a browser. Confirm it loads with no visible breakage.
  2. Walk each Mermaid diagram (the flowcharts on the page). Confirm it renders properly, without showing raw flowchart text. For diagrams you touched, confirm the rendered shapes match what you described in the surrounding prose.
  3. Mentally walk each vignette in the section(s) you changed. Imagine entering the inputs the vignette describes into the actual tool. Does the described downstream cascade still match what the tool would do? If not, update the vignette.
  4. Confirm every acronym used in the section is either already-defined elsewhere in the guide or expanded on its first appearance in your change.
  5. Open the browser's developer console briefly (press F12 in most browsers, then click the Console tab). Refresh the page. No red error messages should appear. If you don't know how to open the console, ask a colleague who does — or skip this step and rely on the visible-breakage check.
  6. (Technical step — for the maintainer.) Update the Last verified against commit line in the page header to the current short commit hash (the seven-character identifier shown at the top of the project's commit history).
  7. (Technical step — for the maintainer.) Commit the change — that is, save it to the project's shared version history — with a message describing what behavior the update tracks, and push the commit to the project's repository.
